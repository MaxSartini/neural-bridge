Neural Bridge — Phase 5 “Learned Heads” Final Results

An independent critical review of the dense-AGAIN 2 Hz Phase 5 benchmark — the author’s designated final result — paired with a deliberately supportive counter-review, then reconciled into concrete critiques and recommended changes.

Repo: MaxSartini/neural-bridge @ c955d65 Author: Max Sartini Reviewed: 2026-06-25 Focus: evidence_bundle_phase0_to_phase5_20260625 · Phase 5

Bottom line

Phase 5 is not fraud and not grossly leaky — its label-permutation and quality controls are clean, and it shows a small but genuinely fold-robust cortical advantage under one validation protocol. But the headline (PR-AUC 0.21913, “Holy-shit pass”, promote) is over-stated by roughly 2–3×: the honest, architecture-matched effect of the cortical features is ≈ +0.02 PR-AUC, not the advertised +0.047 (vs Phase 4) or +0.072 (vs AR). Critically, the effect reverses sign under temporal blocking — there, random/shuffled-noise controls beat the real cortical features — and the promotion gate is hard-coded so it can never see that failure. The most defensible claim is far narrower than the one the bundle advertises.

This document has three parts: Part I — Critical (Red Team), my adversarial read; Part II — Supportive (Blue Team), the strongest good-faith defense, produced by an independent sub-agent instructed to champion the work; and Part III — Synthesis, where the two are reconciled into prioritized critiques and a change-list. Per your instruction, all documentation claims are judged against the bundled BUNDLE_README.md only; the top-level README/ROADMAP are set aside.

● Part I — Critical Review (Red Team)

Where the methodology and results fail

C1The headline effect does not survive temporal blocking — noise controls beat the real featuresFatal

The cortical features beat their matched noise controls when whole videos are held out (grouped_video, +0.022), but are beaten by those same noise controls when future time is held out (blocked_temporal, −0.021). Two equally valid validation protocols disagree on the sign of the effect. A result that flips sign between cross-stimulus and cross-time generalization is, by definition, not a robust finding.

The most damaging interpretation — and the one the data points to. The gated_ar_pca_mlp head learns a sigmoid gate that mixes an AR pathway with the PCA pathway (fused = gate·pca + (1−gate)·ar, runner L197–198). When PCA is noise, the gate routes around it to AR — which is exactly why the controls are so strong. The cortical features add value only when whole videos are unseen. The simplest explanation is that the PCA features encode video-level / static structure (genre, motion regime, overall “vibe” → base spike rate) rather than moment-to-moment predictive dynamics. Holding out whole videos rewards that static information; holding out future time within the timeline removes the video-identity advantage and the cortical edge vanishes. In other words, Phase 5 may be ranking which kinds of videos have more spikes, not when a spike will occur — which is the claim being made.

Why it matters: the entire project thesis is temporal/predictive (“future arousal spike ranking”). The one protocol that genuinely tests forward-in-time prediction is the one where the signal disappears.

C2The promotion gate is coded so it can never be vetoed by the blocked-temporal failureFatal

This is not a presentation problem; it is in the source. In promotion_gates():

  • L796: grouped = summary[validation_protocol == "grouped_video"] — the beats_controls test is computed only on grouped-video. The gate never requires the real features to beat their controls under blocked-temporal.
  • L828: blocked_temporal_support = blocked_score > ar_only_threshold (0.147) — the “blocked support” flag is set True merely because the real blocked lane clears the weak AR floor, not because it beats the blocked controls. It loses to every noise control (C1), yet the report prints Blocked temporal support: True.
  • L814–817: weak/good/strong/holy_shit pass on absolute thresholds (≥0.18/0.19/0.20) gated by the grouped-only beats_controls.

So recommendation: promote_to_phase6_candidate and holy_shit_pass: True are structurally incapable of being stopped by the way the data actually fails. A gate that can only ever confirm is not a gate.

Rhetoric, too: a pass tier literally named holy_shit_pass (and four green “pass” lines) for a PR-AUC of 0.22 on a 10%-prevalence task signals motivated reasoning baked into the evaluation harness.

C3Effect-size inflation: the advertised deltas compare against the wrong baselinesMajor

The honest question is “how much do the cortical features add, holding architecture and capacity fixed?” That answer is the real-minus-matched-noise gap: ≈ +0.02 PR-AUC (grouped), and negative (blocked). Instead the bundle headlines:

  • +0.047 vs Phase 4 — but Phase 4 is ridge/linear; this delta mostly measures MLP capacity, not cortical signal.
  • +0.072 vs AR — measures capacity + the AR pathway itself, not the cortical increment.

Both conflate “a bigger model” with “the brain features work.” The matched control that isolates the latter (shuffled/random PCA in the same gated head) is reported but never used as the headline number.

Compounding it: the controls were run only for loss = binary (phase5_control_metrics.csv → distinct losses: {'binary'}), yet the promoted number uses loss = regression_plus_binary — a configuration with no matched controls at all. The single most-promoted figure is the one cell that was never subjected to a like-for-like control.

C4Garden of forking paths: the headline is the best cell of a multi-axis sweepMajor

The promoted 0.21913 is the maximum over 2 protocols × 3 losses × 3 model heads (plus the implicit earlier selection of feature and target). It is the best of 3 “real” variants even within its own cell (the other two: 0.18450, 0.14990). Selecting the arg-max configuration and then reporting that configuration’s score as the result, without a multiplicity penalty or a held-out re-confirmation, inflates the apparent effect.

A tell of forking-path selection: the “winning” feature changes every phase — VEATIC’s winner was pca_sequence_128_causal_past_2s_mean, Phase 4’s differs again, and Phase 5’s is temporal_mean_2s_then_pca256. When the winning configuration is unstable across stages, some of each “win” is the sweep selecting noise.

C5Absolute performance is weak, and the headline metric was chosen after the natural one failedModerate

Even taken at face value: ROC-AUC 0.699, top-1% recall 0.040 (i.e. at the sharpest spikes, barely above the 1% base rate), top-10% recall 0.265, continuous Pearson 0.219, continuous MAE that the zero-change baseline still beats. The project openly concedes continuous forecasting fails — and then frames the win on PR-AUC/top-k ranking. Switching to the metric that works after the headline metric fails is legitimate only if flagged as exploratory; here it is presented as the proven core.

C6Reported uncertainty understates cross-video varianceModerate

The promotion JSON quotes std_pr_auc = 0.00524 with seeds: 3 — i.e. seed-only dispersion (re-initialization), which is tiny by construction and makes the +0.047 delta look hugely significant. The honest uncertainty for “generalizes to new videos” is the cross-fold spread. (In fairness — see Part II and the synthesis — I checked this and the grouped effect is in fact fold-robust; but the artifact’s own reported error bar is the wrong one and overstates precision.)

C7Bundled-README headline omits the control context for the blocked numberModerate

Scoped to the bundled doc as instructed: BUNDLE_README.md → “Headline Results” cites “blocked temporal real PR-AUC 0.20712” alongside the wins, presenting it as corroboration. It omits that under blocked-temporal the noise controls (≈0.219) beat that real number. A reader of the bundle alone would conclude blocked-temporal supports the claim; the underlying CSVs say the opposite.

● Part II — Supportive Review (Blue Team)

The strongest good-faith case for the work

Produced by an independent sub-agent instructed to champion Max’s methodology and results. Faithfully condensed; every number was independently re-checked against the files.

“This is one of the most disciplined, self-skeptical ML benchmark harnesses I have reviewed. The rigor is wired into the code and the artifacts, not decorative.”

Genuine strengths (these hold up)

  • Matched, same-capacity controls. random_pca draws Gaussian noise of identical shape fed to the same gated MLP — far stronger than beating a majority baseline. Eight controls run in the same loop as the real lane.
  • Leakage discipline is enforced in code, not promised: train-only standardization and thresholds, inner-validation early stopping inside the train fold, fold-safe Phase-4 PCA reused (never refit on test), uses_future_features = False across all 378 control rows, and seven machine-written audits (transform_leakage_audit, split_leakage_audit, row_join_integrity over 27.3M rows, nan_inf_audit, …) all returning pass.
  • The label-permutation null is the cleanest single result. Retraining the winning head on permuted labels collapses to PR-AUC 0.10428, ROC-AUC 0.513 (chance). This decisively rules out the “it’s all an evaluation bug / gross label leakage” hypothesis.
  • The grouped-video win is fold-robust. Paired per-fold, real beats the best matched control in 5 of 5 video folds (mean +0.019, std 0.005) — not a one-fold or one-seed artifact.
  • Reproducibility infrastructure: SHA-256 checksum manifest + one-shot verifier, git commit recorded per run, fixed seeds, per-feature checksums, evidence frozen separately from heavy caches.
  • Honest scoping & hardware honesty: the bundle explicitly lists what remains unproven; the paid H100 995-video encode is correctly labelled a “data-generation milestone, not a benchmark result”; CUDA is actively barred and CPU fallback refused on the Mac/MLX runtime.

The Blue Team’s best rebuttals to my critiques

  • “0.22 is small” → it is ~2.1× the prevalence floor; ROC 0.70 on a stochastic, future-facing affective event from predicted cortical features is a conventional “moderate-and-real” discriminator.
  • “cherry-picking” → primary target and feature are module constants fixed before the run; the head/loss grid is small; Bonferroni across the 9 grouped real lanes still clears Phase 4; the permutation null is independent of multiplicity.
  • “VEATIC→AGAIN doesn’t transfer” → Phase 5 is trained and validated entirely within AGAIN; it independently replicates the phenomenon on 995 new videos, which is stronger than weight transfer.
  • “the gate thresholds are arbitrary” → they are hard-coded literals (pre-registered, not moved post-hoc).
Notably, even the champion conceded C1. The Blue Team flagged the blocked-temporal control reversal as “the one a hostile reviewer would actually land,” recommended tightening the blocked gate to enforce a control comparison, and spun off a documentation follow-up. When the designated advocate volunteers your central critique as real, that critique is real.
● Part III — Synthesis & Recommendations

Reconciled verdict

The two reviews disagree less than their tone suggests. Both agree the pipeline is clean of gross leakage (label-permutation + audits), that the controls are well-designed and same-capacity, and that the grouped-video advantage is real and fold-robust. They diverge on what that advantage means — and the evidence adjudicates:

What survives scrutiny

  • No fabrication; no gross leakage (perm-null at chance).
  • A small, fold-consistent cortical edge over matched noise under cross-video splits: ≈ +0.02 PR-AUC.
  • Real engineering scale & reproducibility (995 videos, 243,575 rows, checksums).

What does not survive

  • The “+0.047 / +0.072” framing (baseline-inflated by ~2–3×).
  • Any temporal/predictive claim — the edge is gone (reversed) under future-time holdout.
  • The promote / holy_shit_pass decision (gate can’t see the failure).

The Blue Team’s defense of C1 — “blocked-temporal is only diagnostic; flexible heads exploit autocorrelation from noise” — actually concedes the case: if a flexible head reaches 0.219 in blocked-temporal from noise, then the grouped 0.219 is also substantially capacity + autocorrelation, and the genuine cortical increment is the small grouped-only residual, of unestablished mechanism.

What I would change (concrete, in priority order)

  1. Make the gate symmetric. Require beats_controls under both protocols, and redefine blocked_temporal_support as “real beats blocked controls,” not “real beats the AR floor.” Under that definition Phase 5 fails — which is the correct outcome. Delete holy_shit_pass.
  2. Run the matched controls for every loss (especially regression_plus_binary), so the promoted cell has a like-for-like shuffled/random comparison. Report the real−matched-control gap as the headline effect (≈ +0.02 grouped, ≤ 0 blocked).
  3. Settle the mechanism with two cheap tests. (a) Add a video-mean cortical control: replace each row’s features with its video’s mean cortical vector — if it matches the real lane under grouped-video, the signal is static/video-level, not dynamic. (b) Score within-video ranking (rank spikes inside each held-out video) so video-level base rates cannot help. If the grouped edge survives (a) and (b), the predictive claim is earned; if not, restate it as a static-correlate finding.
  4. Replace absolute pass thresholds with significance. Use the paired per-fold delta (real − matched control) with a bootstrap/permutation CI; promote only if the CI excludes 0 under both protocols.
  5. Pre-register the primary cell (protocol, loss, head, feature, target) before the run, and report all non-primary cells as exploratory with a multiplicity note.
  6. Re-word the bundled README headline to state the matched-control effect and the blocked-temporal reversal in the same breath as the win.

The one claim that is actually defensible

On dense 995-video AGAIN (243,575 rows @ 2 Hz), a same-capacity gated head over TRIBE-predicted cortical PCA features shows a small, fold-consistent advantage over identically-shaped noise controls when whole videos are held out (≈ +0.02 PR-AUC, 5/5 folds), with a label-permutation null at chance. This advantage does not survive forward-in-time holdout and its mechanism (predictive dynamics vs. video-level static structure) is not yet established.

That sentence is bulletproof. The bundle’s sentence — “+0.047 vs Phase 4, +0.072 vs AR, Holy-shit pass, promote” — is not.
